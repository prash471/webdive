TYPOGRAPHY

System-native and direct.

Use the operating system’s UI sans-serif stack for product and web surfaces. Use a system monospace stack for filenames, formulas, protocol commands, and measured values. This avoids external font requests and keeps the product local-first.

VOICE

Precise, calm, useful.

  • Lead with evidence. State what was measured before recommending action.
  • Name uncertainty. Use “attributed,” “estimated,” and “during this journey” where appropriate.
  • Avoid drama. Prefer “High priority” to “Critical disaster.”
  • Make action concrete. Point to the resource, metric, impact, and next investigation.
MESSAGING

Positioning and approved language

PRIMARY TAGLINE

Go beneath the bundle.

DESCRIPTOR

Local journey performance analysis for Chrome DevTools.

VALUE PROPOSITION

Connect loaded resources to coverage, CPU, long tasks, rendering work, and original modules without sending application data to a backend.

PRIVACY STATEMENT

Captured application data stays in the extension. WebDive has no analytics or hosted analysis service.

Use

  • Measured during this journey
  • URL-attributed sampled CPU
  • Optimization opportunity
  • Local run history

Avoid

  • Guaranteed performance gain
  • Definitely safe to delete
  • Complete causal attribution
  • Anonymous or magical “AI insights”
COMPANY PRESENTATION

How WebDive should appear publicly

Product screenshots

Use real measurements or clearly label illustrative data. Show enough browser context to establish that WebDive is a DevTools product, while removing confidential URLs and source.

Privacy claims

Say “no backend” and “data stays in the extension.” Do not imply that source-map requests are offline; WebDive may request a map declared by an inspected script.

Company boilerplate

WebDive builds local-first developer tooling that turns browser telemetry into specific, explainable performance evidence.
